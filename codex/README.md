# Codex

Локальный каталог изделий из технических стандартов: загрузка документов,
проверка характеристик, поиск, сравнение и сохранение подборов для заказчика.

## Стек

- Python 3.11+
- FastAPI + Jinja2
- SQLite (`data/codex.db`)
- Парсер текстов/PDF (`pypdf`)

## Быстрый старт

Откройте папку `codex` в VS Code. Команды выполняются из этой папки.
Для установки окружения используйте Python 3.11:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe run.py
```

Открыть: http://127.0.0.1:8787. Остановка сервера — `Ctrl+C` в его терминале.

При следующих запусках достаточно последней команды. Активация через
`Activate.ps1` не требуется.

В VS Code выберите `Python: Select Interpreter` →
`.venv\Scripts\python.exe`. Если редактор продолжает подчеркивать установленные
пакеты, выполните `Developer: Reload Window`.

Папку `.venv` следует создавать на каждом компьютере заново. Она содержит
пути к установленному Python и не подходит для передачи вместе с проектом.
Если перенесенное окружение сообщает `No Python at ...`, повторите первую
команду с установленным Python 3.11, затем проверьте зависимости второй командой.

## Что умеет

| Раздел | URL | Функция |
|--------|-----|---------|
| Обзор | `/` | счётчики, быстрые действия, последние изменения |
| Изделия | `/records` | поиск, числовые фильтры, ручной ввод и правка |
| Стандарты | `/standards` | загрузка TXT, MD и текстовых PDF; повторный разбор |
| Проверка разбора | `/accuracy` | сравнение с эталонной разметкой |
| Подборы | `/selections` | сравнение, сохранённые характеристики, CSV |
| История | `/history` | ручные правки, импорт и удаления |
| Резервные копии | `/backups` | создание, скачивание и восстановление базы |

API: `/api/status`, `/api/records`, `/api/accuracy`

### Пример подбора

1. Откройте «Изделия», выберите «Активная мощность, кВт».
2. Введите «От»: `2200 Вт`, «До»: `3 кВт`, нажмите «Найти».
3. Отметьте изделия и нажмите «Сравнить выбранное». Выбор сохраняется в
   текущей вкладке при смене фильтров; его можно очистить отдельной кнопкой.
4. Проверьте отличия, укажите название и заметку, сохраните подбор.
5. В сохранённом подборе нажмите «Скачать CSV» или «Печать».

Одновременно сравниваются до 12 изделий. CSV использует UTF-8 с BOM и
разделитель `;`, подходит для открытия в Excel. Характеристики сохраняются
снимком: последующие изменения и удаление изделий не меняют старый подбор.
Для подборов из прежней версии, где снимка не было, интерфейс показывает
предупреждение и доступные текущие данные.

Числовой фильтр поддерживает мощность, напряжение, массу, температуру и срок
службы. Значения переводятся в единицы выбранной характеристики, границы
включаются. Диапазон изделия должен целиком попадать в заданные границы.
Отсутствующие, неоднозначные значения (например, `380/220 В`) и значения
с другой физической размерностью не подходят. Активная мощность (кВт) и
полная мощность (кВА) учитываются отдельно, без автоматического пересчёта.

Пример API: `/api/records?parameter=power_kw&minimum=2200%20Вт&maximum=3`.

### Ручные правки и проверка ввода

Изменённые поля и отдельные характеристики защищаются от повторного разбора.
Удалённая вручную характеристика также остаётся удалённой. Импорт обновляет
остальные значения; карточка показывает отличия от документа. Связь с
документом сохраняется при ручном изменении его обозначения.

Формы используют единые правила проверки. При ошибке база и журнал не
изменяются, ввод остаётся в форме. Старая версия формы не перезаписывает
новые изменения из другой вкладки: программа предлагает проверить карточку.
История доступна в карточке изделия и в отдельном разделе.

### Резервное копирование

На странице «Резервные копии» создайте копию и скачайте её вне папки
программы. Локальные копии находятся в `data/backups/`.
Это согласованная копия SQLite: изделия, стандарты, сохранённый текст
документов, защищённые правки, подборы и журнал. Исходные PDF и TXT, а также
файлы эталонной разметки в неё не входят; сохраняйте их отдельно.

Для восстановления выберите файл `.db` до 50 МБ и отметьте подтверждение.
Программа проверяет целостность, схему и связи, подготавливает обновление
старой схемы на временной копии и сохраняет текущую базу с пометкой
`before-restore`. Неверный файл не меняет текущую базу. Сохранённый текст
документов остаётся доступен для скачивания после восстановления; повторный
разбор использует исходные файлы в текущей папке `data/standards/`.

### Тема оформления

Переключатель «Тёмная тема» внизу боковой панели меняет оформление всех
разделов: включён — тёмная тема, выключен — светлая. При первом открытии
используется тема системы. Выбор сохраняется в браузере и применяется
при переходах между страницами и повторном открытии программы.
Переключатель доступен с клавиатуры: `Tab`, затем `Пробел` или `Enter`.

## Схема БД

- `standards` — исходные документы
- `extracted_fields` — поля после парсера
- `records` — нормализованные записи
- `selection_results` — сохранённые подборы
- `change_log` — журнал ручных правок

## Тестовые данные

`scripts/seed_standards.py` создаёт **10 учебных ТУ** (оригинальные фикстуры, не копии ГОСТ) и эталонную разметку.

Точность считается **по полям** (`document_id`, `title`, `product_name`, `params`, `constraints`, `notes`) и агрегируется в field accuracy. Цель приёмки: ≥ 95% на ≥ 10 стандартах.

## Как подставить свои стандарты

1. Положите файлы в `data/standards/`
2. Для замера точности добавьте JSON с теми же именами в `data/golden/`
3. Нажмите «Повторить разбор всех» на `/standards`. При старте импорт из папки
   выполняется автоматически только при пустой таблице стандартов.
   Повторный разбор сохраняет ручные правки. Если новая версия документа
   загружена под другим именем, оставшийся старый файл не подменит её.

Загрузка через интерфейс проверяет документ до сохранения. Поддерживаются
TXT/MD в UTF-8 или Windows-1251 и текстовые PDF, до 10 МБ и 100 страниц.
Пустые, повреждённые, зашифрованные PDF и сканы без текста дают понятное
сообщение. При пакетном разборе ошибка одного файла не останавливает остальные.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe scripts/integration_test.py
```

Оба набора используют временные базы. Интеграционная проверка сама поднимает
локальный сервер на свободном порту и останавливает его после проверки
форм, импорта, сравнения, CSV, истории и восстановления.

Для отдельного запуска на другой папке данных можно задать переменную
окружения `CODEX_DATA_DIR`. Основная база при этом не используется.
Существующая база обновляется при запуске программы без удаления записей.
